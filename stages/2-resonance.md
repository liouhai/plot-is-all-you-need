# Resonance 共鸣

目标：让用户**看着图**选出方向。用户往往说不清想要什么，但一眼就知道喜欢哪张。
所以能摆图就不要提问，能给两张图对比就不要用文字解释区别。

## 开始之前：弄清两件事

1. **这张图给谁看。** 期刊正文、补充材料、答辩、组会、海报、公众号，受众不同，合适的图就不同。
   用户的话里已经说了就不要再问；没说就问这一句。
2. **数据长什么样。** 自己打开数据看：有哪些列、多少行、几个分组、数值范围。不要拿数据的问题去问用户，
   除非有会改变图的含义的歧义（比如分不清哪一列是分组）。用户没有数据、只有用途，也可以继续，见文末。

## 找图

1. 读两个图库的 `INDEX.md`，按「用途」和「需要的数据」筛出候选。只选用户数据画得出来的图。
   索引每张图一行，图库有几百张时不要整份读进来：先看开头几行（那里列着所有用途词和各自的张数），
   再用 `grep` 按用途词把相关的行取出来。
2. **打开候选图确认。** 索引只是文字，真正合不合适要看图。可以先用 `contact_sheet.py sheet` 把候选拼成一张自己看，
   再对拿不准的读卡片或原图。
3. **看完觉得不对路，就扩大范围再找**，不要拿勉强的候选去凑数。常见的不对路：用途对但数据形状撑不起来；
   候选全是同一种气质；没有一张适合这次的受众。扩大的办法依次是：把用途放宽到相邻的词、
   不限张扬度、把低质量图也算上（只参考结构）、看其他类型的图能否借用结构。
4. 扩大之后图库里仍然没有合适的，就如实告诉用户这一类图库里缺，建议补图；
   同时可以按你自己的判断提一个图库之外的方案，画成草图放进样板册，并标明"不在图库中"。

## 摆样板册

```bash
python scripts/contact_sheet.py sheet --out <临时目录>/sheet-1.png \
  "<id>::贴近你的口味" "<id>::我的推荐" "<id>::我的推荐" ...
```

- 每轮 6–9 张，自动标上 A、B、C……
- **第一轮要拉开差距**：从平铺直叙到花里胡哨都要有（参考卡片的张扬度），让用户先定大方向。
- **每一轮都要同时有两类图**，并在图上标明：
  - 「贴近你的口味」：依据 `taste.md` 和本次对话里用户表达过的喜好；
  - 「我的推荐」：你认为最适合这次受众和数据的图，不管它是否合用户平时的口味。
  只迎合用户口味是偷懒；发表和展示的图最终是给受众看的。两类都摆出来，让用户自己权衡。
  还没有任何口味信息时，第一轮可以全部是「我的推荐」。
- 把样板册展示给用户，配一段简短的文字：
  - 每张「我的推荐」附一句理由，说清为什么适合这次的受众或数据；
  - 卡片上有提醒（caveat）的图，照常摆出，附上那句提醒；
  - 告诉用户可以怎么回答：选一张，或者组合，比如"B 的布局 + E 的配色"。

## 数据在手时：直接摆草图

用户的数据已经拿到、草图画得快的时候，不必先摆图库样例。你自己看过候选图之后，
直接用真实数据画 4–6 种画法的草图，拼成样板册给用户挑：

- 用户已有一版图的话，把它也放进样板册作对照；
- 每张草图说明借自图库里哪张图（id 加一句话），用户想看原图就摆出来；
- 每张草图同样要标「贴近你的口味」或「我的推荐」。

## 读懂用户的选择

用户可能说"B"，也可能说"A 的窗户、C 的地板"。用这六个部件来理解和确认他们要的是什么：

**结构布局 / 图形元素 / 配色 / 文字与标注 / 装饰细节 / 图例与色条**

用户的话含糊时（"颜色淡一点""再高级一点"），不要追问定义，再摆图让他们指：

- 想换颜色：`python scripts/contact_sheet.py swatches --out pal.png <id>` 会列出这张图有过的所有配色，
  也可以从别的图的卡片里取配色；
- 想换感觉：摆 2–3 张在那个方向上差别明显的图。

## 收窄，然后用真实数据定稿

- 再用 1–2 轮把方向收窄到 2–3 个。每一轮都比上一轮更接近，而不是换一批不相干的图。
- **最后一轮用用户的真实数据画草图**：2–3 个方向各画一张（按 `3-rendition.md` 画，草图不必精修），
  拼成样板册让用户做最终选择。同一种图换了数据，观感可能差很多，用真实数据比过才算数。
- 用户在前面某一轮已经给出明确的选择（指定了哪张图、取哪些部件），就不必再凑一轮草图，直接进入 Rendition；
  草图比较是为拿不定主意的时候准备的。
- 用户定下之后，把"从哪张图取哪个部件"整理成一份清单，带着它进入 Rendition。

## 快速路径："你定"

用户不想选的时候，你自己完成上面的筛选，挑出最合适的三个方向：把首选用真实数据直接画成成品（Rendition + Appraisal），
交付时附上另外两个方向的样例图，并说一句为什么首选是它。用户不满意可以立刻换另一个。

## example 选图：用户给了例图

1. 认真看例图，像写卡片一样弄清它的用途、需要的数据和六个部件的特点。
2. 问用户要不要把这张例图收进图库（要就走 `ingest.py`）。
3. 摆一张样板册：用户的例图、图库里最接近的几张、再加两三张**同一用途但气质不同**的图（标「我的推荐」）。
   用户带例图来，说明已经有方向，但他们未必知道还有更合适的画法，摆出来让他们自己比。
4. 用户的数据画不出例图那种结构时，直接说明缺什么数据，并给出数据撑得起的最接近的候选。

## 品味记录

`taste.md` 记着用户以往的选择。它只用来决定「贴近你的口味」摆哪些图，**不用来排除任何图**。
每次用户做出选择或明确否决后追加一行：

```
2026-10-03 | 期刊正文 | 选了 <id> 的布局 + <id> 的配色 | 否决 3D 和大面积渐变 | 想要"安静但不土"
```

## 没有数据时

用户只有用途没有数据，同样可以选图，只是省掉"数据画不画得出"这层筛选，最后一轮的草图用模拟数据画，
并且按 `SKILL.md` 的底线在图上标明"示例数据"。
