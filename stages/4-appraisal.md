# Appraisal 品评

目标：成品交到用户手里之前，先由你对照样例看一遍；之后让用户并排比较、做决定。
代码跑通不等于图画对了，只有看图才知道。

## 自己先看

把成品 PNG 打开看，同时打开样例图，检查三件事：

1. **点名的部件到位了吗。** 对照 Rendition 写下的部件清单逐条看。用户要的是 A 的布局、C 的配色，
   成品里就要认得出这两样。
2. **有没有硬伤。** 文字重叠、标签被裁掉、图例压住数据、字小到看不清、中文显示成方框。
3. **画出来的数值和数据一致吗。** 挑几个点核对：最大和最小的类别对不对、数量级对不对、分组有没有错位。
   好看但画错的图比难看的图危害更大。

发现问题就改，改完重新渲染再看。最多自己改 3 轮；3 轮后仍有解决不了的问题，如实告诉用户是什么问题、
你试过什么，不要把有硬伤的图当作成品交出去。

## 给用户并排看

```bash
python scripts/contact_sheet.py compare --out <临时目录>/compare.png \
  --labels "样例 A,样例 C,成品" <id-A> <id-C> figures/<名字>.png
```

把对照图展示给用户，简短说明：从哪张图取了什么、有没有做不到的地方、图上有没有需要注意的提醒。
然后由用户决定通过，或者提意见。有意见就回到 Rendition 修改，或者回到 Resonance 换方向。

## 用户满意之后

1. **问一句：要不要把这张图收进图库？** 用户同意再收。
   - 成品用的是模拟数据，或用户确认数据可以公开：放进 `gallery/`，连同脚本。
   - 成品用的是真实研究数据：放进 `gallery-local/`；或者换成模拟数据重画一份放进 `gallery/`。
     `gallery/` 会随技能公开，不能把用户没发表的数据带出去。
   - 入库步骤：`python scripts/ingest.py --gallery gallery <png>`，把脚本复制成同名 `.py`，
     脚本读的数据文件也一并放进去（同名 `.csv`，脚本里改成读它），保证别人拿到后能直接运行；
     按 `1-appreciation.md` 写卡片（`code` 填脚本文件名），然后重建索引。
   - 样例图的卡片 `code` 字段还空着的话，把它指向这份脚本，下次有人选到同一张样例就能直接复用。
2. **在 `taste.md` 追加一行**，记下这次选了什么、否决了什么。格式见 `2-resonance.md`。
