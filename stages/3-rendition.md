# Rendition 演绎

目标：用用户的数据，把选中的图重新演绎出来。是演绎，不是临摹：学的是样例的画法和气质，
画的是用户自己的数据和结论。

## 动手之前

1. **打开选中的样例原图和它的卡片。** 不要凭记忆或凭卡片上的文字去画，文字丢掉的细节正是好看的来源：
   线有多粗、留白多少、标注放在哪。
2. **看卡片的 `code` 字段。** 有现成脚本就从它出发改，不要重写。
3. **写下部件清单。** 用户选的是组合时尤其要写，例如：

   ```
   结构布局   ← A：环形排布，大组之间留缺口
   配色       ← C 的第 3 套配色：#264653 #2a9d8f #e9c46a #f4a261 #e76f51
   文字与标注 ← A：柱顶直接写数值
   其余       ← A
   ```

   这份清单在 Appraisal 阶段要逐条核对。

## 数据

- 数据的读取、清洗、变形都在脚本里完成，不要改动用户的原始文件，也不要让用户先去整理数据。
- 数据不足以支撑这张图时，明确告诉用户还缺什么，不要自己编数补上。
- 用户没有数据时用模拟数据：让它的规模和分布像这类研究里的真实数据，在图的角落标"示例数据"，
  并在脚本开头用注释标出替换真实数据的位置。

## 画

- 用 Python，任何包都可以，目标是画出效果，不必拘泥于某个库。优先用环境里已经装好的包。
- 某种结构确实需要没装的包才画得好（比如弦图、环形布局），先问用户是否安装。
  用户不同意，就用现有的包画一个接近的版本，并告诉用户差在哪里。
- 颜色从样例图上取：卡片 `palettes` 里只有主色，渐变色带、浅色底纹、灰色辅助线这些要在图片的对应位置取样。
  低质量图的颜色已经失真，配色改从别的图取。
- 样例里的数据、变量名、标题、水印都不要搬过来。标签用用户数据里的真实名称。
- 尺寸默认沿用样例的宽高比。用户提到具体期刊时，按该期刊的栏宽来定
  （常见的单栏约 89 mm、双栏约 183 mm，以期刊的投稿须知为准）。
- 图里有中文时先确认字体可用，否则会出现方框。

## 交付

默认保存到用户当前项目的 `figures/` 文件夹，三样东西用同一个名字：

- `<名字>.png`：300 dpi，用来看和插入文档；
- `<名字>.pdf`：矢量图，用于投稿；
- `<名字>.py`：画图脚本，可以独立重新运行，数据路径写在开头。

选图阶段的草图不需要这三样，只出一张 PNG 放在临时目录即可。

画完不要直接交给用户，先进入 Appraisal。
