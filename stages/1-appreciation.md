# Appreciation 鉴赏

目标：让图库里的每张图都有一张你写的卡片。之后的选图全靠这些卡片把合适的图找出来，
所以卡片写得越具体，摆到用户面前的候选图就越对路。

## 加图

```bash
python scripts/ingest.py <图片或文件夹>            # 默认进 gallery-local/
python scripts/ingest.py --gallery gallery <图片>   # 进公开图库（会随技能公开，带水印或含未发表数据的图不要放）
python scripts/ingest.py                           # 用户直接把图拖进了图库文件夹时，用这个补登记
```

脚本会把长边压到 2000 像素、建一张空卡片（`appreciated: false`），并做去重：

- **换色变体**：结构和库里某张图一样、只是颜色不同。图不入库，它的配色记到那张图卡片的 `palettes` 里。
- **⚠ 可能重复**：相似但拿不准。图已入库，用 `contact_sheet.py compare` 把两张并排给用户看，由用户决定留哪张。
- 截图、带黑边、分辨率很低的图会被标记 `low_quality: true`。它们的结构仍可参考，但颜色已经失真。

## 删图

用户直接删掉图片文件即可。之后运行 `python scripts/build_index.py --prune`，清掉留下的卡片。
如果用户要求只下架图片、保留文字，将同名 `.md` 放入 `gallery/cards-only/` 并保留内容；这个子目录不参与可展示图片索引，也不受根目录 `--prune` 清理。只清理 GitHub 时，不删除本地私人收藏。

## 给一张图写卡片

打开图片认真看，然后填写同名的 `.md` 卡片。完整示例：

```markdown
---
title: 环形分组柱状图（内圈图例）
kind: 数据图
purpose: [组间比较, 排序]
data: 一组类别（15–40 个）各有一个数值，类别可以再归成 3–6 个大组
loudness: 4
caveat: 柱子沿半径方向伸展，外圈的柱子看起来比同样数值的内圈柱子更大，精确比较数值时会吃亏
low_quality: false
code:
appreciated: true
edited: false
palettes:
  - "#5e0075 #0d01e8 #bc0032"
---

**评价**：把一长串类别绕成一圈，省掉了横向柱状图那种又高又窄的版面，中心留白正好放图例。
适合"成员很多、想让人先看到整体格局再看个别突出者"的场合，比如各基因、各站点、各特征的强度总览。

**部件亮点**
- 结构布局：环形排布，大组之间留出缺口，一眼能看出分组边界
- 图形元素：圆角柱，柱顶直接写数值，省掉了径向刻度
- 配色：同一大组用同一色系的深浅变化，组间换色相
- 文字与标注：类别名沿切线方向旋转，始终朝外可读
- 装饰细节：柱子带白色细描边，相邻柱不会粘连
- 图例与色条：图例放在圆心，不占外部空间
```

各字段怎么写：

- **title**：一眼能认出这张图的名字，先说图型，再说最有辨识度的特点。
- **kind**：只能是这四个之一：数据图 / 流程图 / 示意图 / 组合图。组合图指一张图里拼了两种以上不同的图型。
  不要自造"关系图""时序图""分布图"这类新类型，它们都是数据图。
- **purpose**：这张图适合讲什么。**只能从下面 16 个词里选 1–3 个，原样照抄，不要改写，不要造新词。**
  选图时是按这些词检索的，写成"分布展示""情景比较"这样的近义词，这张图就再也搜不到了。
  词表：分布、组间比较、相关关系、趋势变化、构成占比、排序、特征重要性、模型解释、模型性能、
  空间分布、网络与流向、多指标综合、层次结构、集合关系、流程示意、不确定性。
  拿不准时这样归：方法、情景、模型、时期之间的对比都算"组间比较"；地图、剖面、场图算"空间分布"；
  降维散点、热图矩阵、平行坐标算"多指标综合"；预测对实测、ROC、残差算"模型性能"；
  置信带、集合成员的范围算"不确定性"。没有完全合适的就选最接近的一个。
  确实需要新词时，先问用户，同意后加进 `scripts/cards.py` 的 `PURPOSES`，不要直接写在卡片里。
- **data**：用大白话说它需要什么样的数据，包括大致的数量级。以后要靠这句话判断用户的数据能不能画这张图，
  所以要写"多个类别 × 多个指标的数值表"这种形状，而不是原图里的具体变量名。
- **loudness**（张扬度，1–5 的整数）：只用来在选图第一轮拉开风格差距，不代表好坏。
  1 = 平铺直叙：常规图型，默认或接近默认的样式，黑白灰加一两种颜色；
  2 = 朴素但用了心：常规图型，配色或排版做过调整；
  3 = 中规中矩：有设计感但克制；
  4 = 有明显的设计手法：嵌套、组合、非常规坐标、大量标注；
  5 = 花里胡哨：环形、3D、多层嵌套、大面积渐变。
  五档都是用户要选的风格。平铺直叙的图不是次品，不要因为朴素就不收，也不要把它往高分上靠。
- **caveat**：只有当读者可能读错数值，或者缩小印刷后会看不清时才写，一句话说清在什么情况下出问题。
  它是给用户的提醒，不是否决；这张图照常参加选图。没有就留空。
- **评价**：像向朋友介绍一张你欣赏的图。好在哪里、适合讲什么故事、哪个细节值得学。要具体到这张图，
  "配色和谐、布局合理"这种放在任何图上都成立的话没有信息量。
- **部件亮点**：六个部件各一句。用户会说"要 A 的配色、C 的布局"，你要靠这六句知道该从这张图取什么。
  某个部件确实平平无奇，就写"常规"。
- **palettes**：脚本填的，不用动。第一条是这张图自己的配色，后面是它的换色变体。
  记的是面积最大的几个彩色，不含灰、近白和近黑；渐变色只留下其中几档。它用来挑方向，精确取色要回到图上。
- **code**：如果这张图已有能画出它的脚本，填脚本路径。
- **卡片只写鉴赏内容**，不写出处、作者、许可。别人的图的出处统一记在 `THIRD_PARTY_NOTICES.md`。
- 低质量图：配色那一句写"截图失真，不作取色参考"。

写完把 `appreciated` 改成 `true`。全部处理完后运行 `python scripts/build_index.py`。
脚本会检查 `kind`、`purpose`、`loudness`，输出里有 ⚠ 就照提示改卡片，改到没有 ⚠ 为止。

## 往公开图库 `gallery/` 收图的边界

用户让你"多找一些图"时，照下面的边界做。这些边界不写明，不同的 agent 会收来完全不同的东西。

1. **许可**：只收你自己画的图，或原文明确标注 CC BY / CC0 的图。能公开读到不等于可以转载。
   每张别人的图在 `THIRD_PARTY_NOTICES.md` 记一条：作者、标题、原文链接、图号、许可、做过什么改动。
   图注里另有第三方版权声明的图不收。许可拿不准的放 `gallery-local/`。
2. **类型**：默认只收数据图。流程图、示意图只在用户明确要的时候收。
   不收照片、三维渲染图、讲公式的示意图，也不收原文拿来当反面例子的图。
3. **多样**：同一篇论文最多收 2 张，而且两张的图型要不同。优先收单幅图；
   整页的多面板拼图只在它的拼法本身值得学的时候收。至少覆盖用户点名的学科。
4. **风格**：张扬度 1–5 每一档都要有，包括平铺直叙的。
5. **版面**：长宽比超过 3:1 的长条图缩小后看不清，不收。
6. **入库**：用 `python scripts/ingest.py --gallery gallery <图片>`，脚本报"换色变体"或"可能重复"的按上文处理；
   写完卡片运行 `build_index.py`，改到没有 ⚠。
7. **只动这次任务的文件**：新图、新卡片、`THIRD_PARTY_NOTICES.md` 和索引。
   不要删除、改名或改写图库里已有的图片、卡片、脚本和数据文件。

## 卡片是可以被用户修改的

卡片就是你对这张图的理解，用户可以直接编辑它来纠正你。用户改过的卡片应把 `edited` 设为 `true`，
此后重新鉴赏时跳过它。如果你发现一张 `edited: false` 的旧卡片写得不准，可以重写。

## 一次处理很多张

图多的时候分批做，每批看完就写、写完就存，不要攒到最后。看图时注意和库里已有的图比较：
两张图差别只在数据或标签，就在卡片里互相提一句，选图时可以只摆其中一张。
